# SECURITY, REPOSITORY & WORKSPACE CONSTRAINTS (MANDATORY)

You are operating as an autonomous engineering agent inside this project workspace. You MUST adhere to these strict guardrails at all times:

## 1. Dependency & Registry Isolation

- NEVER query, route, or configure any corporate private registry (e.g., Nexus, Artifactory, internal mirrors).
- ALL package operations (npm, npx, pnpm, yarn) MUST resolve exclusively through the public npm registry: https://registry.npmjs.org/
- Ensure a project-level `.npmrc` file exists at the root containing:

  ```
  registry=https://registry.npmjs.org/
  ```

- NEVER modify the host system's global `~/.npmrc`, environment variables, or global proxy settings.

## 2. Git & Version Control Integrity

- ONLY push code to the user's explicit personal GitHub remote repository (`https://github.com/ratnarakesh/LifeSpokenEnglish.git`).
- NEVER push to, configure, or read from any corporate or internal GitLab, Bitbucket, or GitHub Enterprise endpoints.
- NEVER commit `.env`, `.env.local`, API keys, internal tokens, or sensitive credentials to Git.
- Maintain a strict `.gitignore` covering: `node_modules/`, `.next/`, `out/`, `.env*`, and OS cache files.
- **Versioned commit messages (every push):** each push MUST use the subject format `Version N: <message>`, where N increments by 1 per push (Version 1, Version 2, Version 3, ...). Determine the next N from `git log --oneline` (highest existing `Version N` + 1). If several commits go into one push, squash them into a single `Version N` commit.

## 3. Workspace Boundaries & Code Quality

- Restrict all file reads, writes, terminal executions, and builds strictly to this project root directory. Do not inspect or touch parent directories.
- Deliver 100% bug-free, type-safe Next.js (TypeScript) code that passes `npm run build` with zero compiler errors.
- Ensure all assets, mock data, and phone links are strictly tied to the public client ("LIFE Spoken English").
- **Typography:** NEVER use em dashes (U+2014) or en dashes (U+2013) anywhere in the repository (copy, metadata, alt/aria text, docs, comments). Use a plain hyphen (" - "), "to" for ranges, or restructure with colons, commas or periods. The E2E suite asserts this on the rendered page.
